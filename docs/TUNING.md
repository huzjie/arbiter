# 调参指南

## 1. 置信度阈值 threshold（最关键）

跑 `python -m arbiter bench` 看「升级率 / 成本节省 / 路由准确率」三条曲线：

- 阈值从 0.85 调高 → 升级率上升、成本节省下降、准确率上升；
- 阈值调低 → 相反。

经验法则：**先保住目标准确率，再往低调阈值抠成本**。若 decider 与 reasoner
成本比是 1:100，阈值可适当调低；若误判代价高（如医疗/金融），阈值调高。

## 2. mock 后端 skill

`skill` 是「决策准确率」的模拟旋钮，`bench` 会从 0 扫到 1 展示整条单调曲线。
把它理解成「你的小模型有多强」——越强，越多的请求能在便宜层就地解决。

## 3. 预算 budget

给 `budget.max_cost` / `max_latency_ms` 设上限，路由会在预算耗尽时停止升级、
就地采纳。适合「成本硬封顶」的场景。

## 4. 缓存 cache

- `semantic_threshold` 调高 → 语义缓存更严格（少误命中、多漏命中）；
- `ttl_seconds` 控制结果新鲜度。

## 5. 温度 temperature

决策 softmax 的温度：调低让概率更尖（更敢拍板）、调高更平（更保守）。
