# 核心概念：分层决策路由

## 1. 决策模型（Decider）vs 生成模型（Generator）

大模型默认是「生成器」——根据提示词逐 token 生成答案。但很多高频判断
根本不需要生成：**意图分类、打分、选路、是/否**，本质上是在一个**封闭
选项集**里挑一个。

决策模型（如 AWS Strands Decider 系列）把「语言头」换成「指针头」——
一次前向对每个候选打分，直接输出概率分布，不生成文本。好处：
- 输出空间小、可控（不会跑偏、不会幻觉出选项之外的东西）；
- 可以做概率校准、接门控；
- 小模型也能做好，成本低。

## 2. 分层（Hierarchical）

```
便宜小决策模型（高频、低难度的判断）
        │  置信度 >= 阈值 ？采纳
        ▼  否则升级
贵大模型（低频、高难度的兜底）
```

关键洞察：**大模型负责推理、小决策模型负责高频判断**。把海量的简单判断
下沉到便宜模型，把少数难判断上浮到贵模型，整体成本大幅下降、速度大幅上升。

## 3. 置信度门控（Confidence Gate）

升级与否由「决策模型的 top1 置信度」决定。阈值是关键旋钮：
- 阈值低 → 更多请求就地采纳 → 省得多，但可能放过「自信但错误」的判断；
- 阈值高 → 更多请求升级 → 更稳，但省得少。

## 4. 预算（Budget）

成本 / 延迟预算作为升级的硬约束：预算耗尽就不再升级，就地采纳当前最优。
